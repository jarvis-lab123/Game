# Voki Phase 1 – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (Native, gewählt vom Nutzer: "durchbauen"). Steps use checkbox syntax.

**Goal:** Vokabel-App Voki (PWA + Windows/Tauri) mit Lernleiter, Tipp-Bewertung, FSRS und Prüfungsmodus, nutzbar vor dem 18.11.

**Architecture:** Eine Vite/React/TS-Codebasis in `voki/` (Monorepo `jarvis-lab123/game`). Reine Logik in `src/lib/` (ohne DOM, voll getestet), Persistenz in `src/db/` (Dexie), UI in `src/ui/`, Plattform-Adapter in `src/platform/`. Tauri-Hülle in `src-tauri/` lädt dieselbe `dist/`.

**Tech Stack:** Vite, React, TypeScript, Tailwind v4, Framer Motion, Dexie + dexie-react-hooks, ts-fsrs, vite-plugin-pwa, Vitest, Tauri 2. (Recharts erst Phase 2 – Statistik-Screen ist Phase 2.)

**Spec:** `voki/docs/VOKI_KONZEPT.md`

## Global Constraints
- Kosten 0. Kein Backend in Phase 1.
- Pages-URL: `https://jarvis-lab123.github.io/game/voki/` → Vite `base` = `/game/voki/` für PWA-Build, `./` für Tauri-Build.
- Breakpoint 900 px: < 900 Bottom-Nav eine Spalte, ≥ 900 Seitenleiste.
- Lernkarte max. 640 px breit, Wort ≥ 32 px. Inter, ein Akzent Blau, Dark/Light nach System.
- Animationen 150–250 ms, `prefers-reduced-motion` respektieren. Touch-Ziele ≥ 44 px.
- FSRS: `request_retention 0.90` (aus Settings), `maximum_interval 365`, `enable_fuzz true`.
- Alle UI-Texte Deutsch, kurz.

## Review Focus
1. TSV mit Windows-Zeilenenden (`\r\n`), BOM, leeren Zeilen, Anführungszeichen → sauber parsen, keine leeren Notes.
2. Eingabe mit mehreren Lösungen „die Bäckerei; der Bäcker“ und Klammern „(sich) erinnern“ → jede Variante akzeptieren, Klammerinhalt optional.
3. Testdatum heute/gestern/in ≤ 2 Tagen → keine Division durch 0, keine negativen Zahlen; nach dem Test normaler Modus.
4. Reload mitten in der Session → kein Datenverlust, Karten-Stufe bleibt erhalten.
5. Backup-Import einer fremden/kaputten Datei → Fehlermeldung, bestehende Daten bleiben unangetastet.

### Task 1: Gerüst + Datenmodell
**Files:** `package.json`, `vite.config.ts`, `tsconfig*.json`, `index.html`, `src/main.tsx`, `src/index.css`, `src/db/db.ts`, `src/lib/types.ts`
- Produces: `db: VokiDB` mit Tabellen `decks, notes, cards, logs, settings, meta`; Typen `Deck, Note, Card, ReviewLog, Settings, Direction, Stage` exakt wie Konzept §3 (+ `Card.introducedAt?`, `Card.lastResult?`).
- Indizes: `cards: id, deckId, noteId, [deckId+stage], fsrs.due`; `logs: id, cardId, deckId, timestamp`.
- [ ] `npm run build` grün, `npm test` läuft.

### Task 2: Bewertungslogik (TDD) – `src/lib/grade.ts`
- `normalize(s): string` (trim, Mehrfach-Leerzeichen, lowercase, Satzzeichen am Ende weg, typografische Apostrophe → `'`).
- `stripAccents(s)`, `levenshtein(a,b): number`, `splitArticle(s): {article?: string, rest: string}` (fr: le/la/l'/les/un/une/des; en: the/a/an/to).
- `solutions(translationOrTerm): string[]` (Split an `;` und `/`, Klammer-Teile optional → beide Varianten).
- `gradeAnswer(input, expected, opts:{strictAccents, durationMs, language}): {verdict:'correct'|'accent'|'typo'|'article'|'wrong', rating: Rating, matched: string}` nach Tabelle §5.4 (correct→Good, accent→Hard bzw. Again bei strict, typo (Distanz 1, Länge ≥ 6)→Hard, article→Again, wrong→Again).
- `diffChars(input, expected): {ch:string, ok:boolean}[]` für Farbmarkierung.
- Tests zuerst: `src/lib/grade.test.ts` (Normalisierung, Akzent, Artikel „le/la boulangerie“, Levenshtein-Grenzen 5/6 Buchstaben, Mehrfachlösungen, Klammern, Rating-Zuordnung).

### Task 3: FSRS + Lernleiter + Session (TDD) – `src/lib/srs.ts`, `src/lib/session.ts`
- `newFsrsCard(now): FSRSCard`, `review(card, rating, now, retention): {card, log}` (ts-fsrs `fsrs(generatorParameters({...}))`).
- Lernleiter `advanceLadder(card, step:'intro'|'mc'|'type', correct:boolean, now)`: intro→mc, mc ok→type, type ok→review + erster FSRS-Eintrag (Good); Fehler → bleibt, Requeue.
- `buildQueue(cards, {now, newLimit}): Card[]` fällige zuerst (nach due), neue/lernende alle ~3 eingestreut, Decks gemischt.
- `requeueOffset(): 3..5`. Rückstand-Bremse: > 150 fällig → newLimit 0 (außer Prüfungsmodus).
- `estimateMinutes(reviews, news)` (Review 10 s, neu 45 s).

### Task 4: Prüfungsplanung (TDD) – `src/lib/exam.ts`
- `daysUntil(examDate, now)` (Kalendertage, lokal).
- `newPerDay(unlearned, examDate, now)`: `ceil(unlearned/(days-2))`; days ≤ 2 → 0; Beispiel 190/14 → 16.
- `examWarning(n) = n > 40`.
- `readiness(cards, examDate)`: Mittel der Retrievability am Testtag (ts-fsrs `forgetting_curve`/`get_retrievability`), ungelernte Karten zählen 0; getrennt `toNative` (Erkennen) / `toTarget` (Schreiben).
- `isExamActive(deck, now)`: examDate ≥ heute.

### Task 5: TSV-Import + Backup – `src/lib/tsv.ts`, `src/lib/backup.ts`, `src/db/repo.ts`
- `parseDelimited(text): {delimiter, rows: string[][]}` (auto Tab/`;`/`,`, BOM, `\r\n`, Quotes).
- `mapRows(rows, mapping): NoteDraft[]`, Duplikate markieren (gleicher normalisierter term im Deck).
- `importNotes(deckId, drafts, directions)` in einer Transaktion (bulkAdd) – Test: 190 Zeilen < 1 s, 190 Notes, 380 Cards bei 2 Richtungen (fake-indexeddb).
- `exportBackup(): BackupV1`, `validateBackup(json)`, `restoreBackup(b)` (alles ersetzen in einer Transaktion, vorher validieren).
- `CLAUDE_PROMPT` exakt aus §4.1.

### Task 6: UI-Grundgerüst + Design-Tokens

### Task 7: Session-Screen
- Stufen: Intro (Eselsbrücke-Feld), MC (4 Optionen, Ablenker aus Deck, gleiches Genus bevorzugt, Tasten 1–4), Tippen (Bewertung, Diff, Abtippen nach Fehler, „Ich hatte recht“, „war zu leicht“), Umdrehen (Space, 1–4).
- Akzent-Leiste `é è ê ë à â ç î ï ô û ù œ æ « »`, Alt+Buchstabe zykliert (`src/lib/accents.ts`, getestet).
- Shortcuts: Enter prüfen/weiter, Space umdrehen, 1–4, Esc beenden. Zeitbudget 15 Min → „Fertig für heute“ + „Noch 5 Min?“.

### Task 8: Heute, Decks, Import-Screen, Einstellungen
